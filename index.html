The problem

vibe coding vs. production

Vibe coding gets you to a demo. It rarely survives production.

In the AI era, pre-seed and seed startups race to ship and raise. But when an app lacks sound engineering foundations, velocity grinds to a halt.

01

No one owns the architecture

AI writes code quickly, but it doesn't architect scalable systems. When the initial structure is flawed, every new feature sits on an unstable crack.

02

Fixes create cascading bugs

Prompting AI to patch bugs in a brittle codebase often introduces two more. Days vanish into prompt battles and token burn while features remain unshipped.

03

Native issues AI can't foresee

Background sync limits, memory leaks, OEM quirks, and app-store compliance only surface on physical devices in the hands of real, paying users.

Runway is time: Early-stage startups typically operate with 12 months of runway. Spending months fighting technical debt is spending the company's life away.

Case studies

Map SDK rescue: the release blocker 10 screens to Compose · 1.5 months
Context
Our forked map SDK was outdated and no longer supported by its maintainers, and its native libraries didn't meet Google Play's 16 KB page-size requirement. We couldn't keep it in production: new features were blocked, and customers were threatening to churn.
What I did
Researched community alternatives and chose a map SDK that worked with our existing map infrastructure. Switching meant rewriting every map screen from XML to Jetpack Compose, across both core products on phone and tablet.
Outcome
Shipped in 1.5 months: 10 screens across people transport and logistics (2 + 2 on phone, 3 + 3 on tablet). Releases resumed, and the company went back to shipping features and earning revenue.

Build speed & code-quality foundations Builds 8–10 → 3–4 min · 80% test coverage
Context
Gradle builds took 8–10 minutes. Features were tightly coupled with no separation of concerns, which made the app hard to scale or maintain. There were no unit tests and no documentation, and this was before AI coding assistants.
What I did
Split the app into multiple modules, optimised the Gradle scripts, built up unit tests, added Detekt for lint checks, and built a CI/CD pipeline that runs the tests and publishes with Fastlane.
Outcome
Builds dropped to 3–4 minutes. Unit-test coverage reached 80%, verified with JaCoCo reports. Detekt enforces a shared coding style, and one command bumps the version, runs the tests and publishes to staging or production.

Case studies

27 broken background syncs, fixed in 2 months Sync issues to near zero · 12 Android engineers
Context
I inherited a legacy codebase and found 27 background data syncs that were failing silently. They caused missing transactions, sales discrepancies and merchants stuck offline, and complaints kept coming in.
What I did
Took the initiative and led the fix: migrated the deprecated background mechanisms to modern Android APIs. I led 12 Android engineers and rolled the changes out gradually, so each step could be verified in production.
Outcome
All 27 shipped within 2 months. Sync issues dropped to near zero, crash-free users rose to 99.3%, and complaints about stuck-offline devices, missing transactions and discrepancies fell sharply.

How I work

0 → 1 Framework

  1. Week 1–2 · Foundations

    Stack & Pipeline Setup

    Choose the right stack (Native vs. React Native / Expo) based on product requirements and runway. Establish clean modular architecture, CI/CD, crash telemetry, and analytics before line one of features.

  2. Month 1–3 · Ship the MVP

    Iterative Build & Store Release

    Weekly test releases to founders and early adopters. Leverage Supabase or Firebase to unblock mobile flows before spinning up dedicated backend teams. Ship to the App Store and Google Play.

  3. Post-Launch · Stabilize & Scale

    Metrics & Team Expansion

    Track real-world crash-free rates, network latency, and store ratings. Modularize features and automate regression tests as team size and feature surface grow.

Engineering Principles

  • AI as a multiplier, not a crutch

    I integrate AI agents daily for test generation, boilerplate, and triage — but always inside a human-verified, sound architecture where every line is understood.

  • Every release through the pipeline

    Releases are automated via CI/CD, never shipped ad-hoc from a laptop. Built from scratch multiple times across high-growth startups.

  • Verification, fastest layer first

    Unit tests run on every commit, automated UI regression on PRs, and physical device validation for OEM-specific quirks and flaky connectivity.
