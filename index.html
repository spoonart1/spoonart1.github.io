How I work

verification first, then the structure that keeps it true

Stability is not a phase at the end. It is the order I do things in.

Verification — fastest layer first

  1. Unit tests

    The cheapest place to catch a regression, and the only layer fast enough to run on every commit.

  2. UI automation

    Gherkin keeps the specs readable by QA and product, not just engineers. This is also where I put AI agents to work writing and maintaining the suite.

    Appium Playwright BDD Gherkin

  3. Manual, on real devices

    For what automation cannot see: OEM quirks, unusual screen sizes, and how the app behaves on a bad connection.

    BrowserStack

Foundations

  • Multi-module

    Android and Java libraries split so builds stay fast and teams stop blocking each other. 37 modules at SWAT Mobility.

  • Clean Architecture

    So the app outlives the team that wrote it, and the next engineer can find things without being told where they are.

  • CI/CD

    Every release ships through the pipeline, never from a laptop. I have built this from nothing twice.
